# Техническое задание — Alim Launcher

**Задача:** создать полноценный, устанавливаемый лаунчер **Minecraft: Java Edition для Windows 10/11 (x64)** под названием **Alim Launcher**. Не макет и не демонстрацию кнопок: все заявленные функции должны реально работать.

## 1. Папка проекта и дизайн

- **Корень проекта:** `D:\mylauncher` — все исходники, зависимости проекта, конфигурации, документацию, сборки и Git-репозиторий хранить здесь. Не удалять существующие файлы пользователя.
- **Исходные ассеты:** `D:\mylauncher\Изображения` — самостоятельно просканировать изображения (концепт интерфейса, фон главного экрана, фон редактора скинов, логотип, лист иконок). Использовать именно их как визуальные референсы и ресурсы. При необходимости аккуратно нарезать лист иконок на отдельные PNG, не портя оригинал.
- **Интерфейс:** воссоздать дизайн концепта максимально близко: тёмное стекло, изумрудно-бирюзовые акценты, фоновая Minecraft-панорама, логотип-куб, левая навигация, профиль, выбор версии/загрузчика и крупная кнопка «Играть». Внутренние разделы оформить в том же стиле. Скриншот-концепт показывает несколько экранов сразу: в работающем приложении оформить их как отдельные вкладки/панели, а не нагромождение окон.
- Качественные плавные hover/press-переходы (150–250 мс), прогресс-бары, скелетоны загрузки, уведомления; поддержка масштабирования Windows/HiDPI, адаптация к размеру окна, русский интерфейс по умолчанию. Никаких неработающих «декоративных» кнопок.

## 2. Основной функционал

1. **Аккаунт:** безопасный вход через Microsoft OAuth в системном браузере (без сбора пароля); проверка владения Minecraft: Java Edition, профиль, ник, аватар, сохранение и обновление токена в защищённом хранилище ОС, выход и смена аккаунта. Учесть необходимые разрешения и регистрацию приложения Microsoft; если требуются действия владельца, ясно перечислить их, не имитировать авторизацию.
2. **Версии и запуск:** список доступных версий Java Edition из актуального официального манифеста Mojang: релизы, старые версии, при включении фильтра — снапшоты. Установка, проверка файлов, загрузка зависимостей, лог запуска, обработка ошибок, кнопка «Играть», история установок.
3. **Загрузчики:** Vanilla, Fabric, Forge, NeoForge, Quilt, OptiFine; поддержка **Forge + OptiFine только для реально совместимых сборок**. Показывать совместимые варианты для выбранной версии Minecraft, не предлагать невозможные сочетания. Для OptiFine предусмотреть ручной импорт официального `.jar` при необходимости; не распространять чужой мод в составе EXE.
4. **Изолированные профили:** отдельные папки игры, модов, миров и настроек у каждой сборки, возможность создать/переименовать/удалить профиль с подтверждением; не затрагивать чужие файлы и обычную `.minecraft` без разрешения.
5. **Моды:** каталог Modrinth (поиск, версии, совместимость, зависимости), установка/удаление/включение/выключение модов, импорт `.jar`, предупреждения о конфликтах. **Текстурпаки:** установка и управление `.zip` в `resourcepacks`, импорт готовых файлов. Желательно аналогично поддержать шейдерпаки.
6. **Скины:** импорт/экспорт PNG, типы Steve/Alex, 3D-превью с вращением, встроенный пиксельный редактор (кисть, ластик, заливка, пипетка, палитра, отмена/повтор, второй слой), форматы 64×64 и старый 64×32. Сохранение локально; применение к Microsoft-профилю — только через доступный официальный API с согласия пользователя.
7. **Папки и настройки:** быстрые кнопки для открытия папок выбранного профиля (`mods`, `resourcepacks`, `shaderpacks`, `saves`, `logs`), выбор корневой папки игры; автоопределение/управление подходящей Java, выбор RAM, разрешения, пути Java, лимита загрузки, темы, языка, поведения окна после запуска.

## 3. Технологии и безопасность

- **Electron + React + TypeScript + Vite**; сборка Windows через **electron-builder (NSIS)**. Minecraft-ядро — актуальные совместимые пакеты `@xmcl/*` либо эквивалентная поддерживаемая библиотека после проверки лицензии и реальных тестов. Для 3D-превью скина — Three.js или надёжный специализированный компонент.
- Разделить UI и системную логику через безопасный IPC; `contextIsolation: true`, `nodeIntegration: false`, строгая проверка входящих данных, безопасное скачивание HTTPS и контроль хешей. Не хранить пароли/токены в Git, логах или исходниках; не встраивать приватные ключи и GitHub PAT в EXE.
- Версии Java определять по требованиям выбранной Minecraft-сборки, а не жестко использовать одну Java для всех. Сетевые ошибки, отмена/повтор загрузок, диагностика и понятные сообщения обязательны.
- Соблюдать лицензии и правила Minecraft, модов и ресурсов; не включать игровые файлы Minecraft в дистрибутив, загружать их из разрешённых источников для авторизованного пользователя.

## 4. GitHub, EXE и автообновления

- Создать Git-репозиторий в `D:\mylauncher`, подготовить `.gitignore`, `README.md`, лицензионные уведомления, скрипты разработки и сборки. После проверки доступа через `gh auth status` создать репозиторий GitHub `alim-launcher` и загрузить исходники; если доступа нет, подготовить команды и явно сообщить, что осталось сделать.
- Настроить **GitHub Actions**: по релизному тегу `vX.Y.Z` собирать Windows x64 установщик `Alim-Launcher-Setup-X.Y.Z.exe` и публиковать его с метаданными обновлений в **GitHub Releases**. Для массового автообновления обеспечить публично доступные релизные файлы; если исходный репозиторий должен оставаться закрытым, использовать отдельный публичный репозиторий только для релизов. Не публиковать исходники/репозиторий публично без согласия владельца.
- Подключить `electron-updater`: проверка при старте и из настроек, уведомление о версии, список изменений, прогресс скачивания, установка при перезапуске, безопасная проверка целостности. Предусмотреть подпись Windows-приложения сертификатом, когда он появится; не выдавать неподписанный EXE за доверенно подписанный.
- **Результат локально:** `D:\mylauncher\dist\Alim-Launcher-Setup-X.Y.Z.exe`, полноценный исходный код и инструкции по выпуску новых версий.

## 5. Приёмка (не пропускать)

- Установить EXE на чистую Windows-машину/чистый тестовый профиль, запустить интерфейс, проверить ресурсы, иконку приложения и все вкладки.
- Проверить настоящий Microsoft-вход, установку и запуск минимум одной Vanilla и одной Fabric-версии; отдельно проверить Forge и остальные доступные загрузчики, а несовместимые сочетания корректно блокировать.
- Проверить импорт/сохранение скина, установку/отключение мода, текстурпак, папки, сохранение настроек, ошибки и работу после перезапуска.
- Выпустить тестовые версии `1.0.0` → `1.0.1`, установить первую и подтвердить, что вторая загружается и устанавливается **внутри приложения** без ручного похода на сайт. Если публикация невозможна из-за отсутствующих ключей/доступов, не заявлять о пройденном тесте и дать точный список блокеров.

**Порядок работы:** изучить содержимое папки и ассеты → реализовать реальную логику → довести внешний вид до совпадения с концептом → тесты → сборка EXE → репозиторий → релиз и проверка автообновлений. Самостоятельно исправлять обнаруженные ошибки и вести `PROGRESS.md` с подтверждёнными результатами. Не заменять работающие функции заглушками и не утверждать, что задача выполнена, пока проверки не пройдены.
